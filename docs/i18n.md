# Internationalization (i18n)

The whole UI, including the default flavours on the board, is available in several
languages. Translation is handled by [i18next](https://www.i18next.com/) and
[react-i18next](https://react.i18next.com/), configured in `src/i18n.tsx`.

## Available languages

| Code | Language | File                                  |
| ---- | -------- | ------------------------------------- |
| `en` | English  | `public/locales/en/translation.json`  |
| `de` | German   | `public/locales/de/translation.json`  |
| `es` | Spanish  | `public/locales/es/translation.json`  |
| `nl` | Dutch    | `public/locales/nl/translation.json`  |

English is the fallback: a key missing from another language is shown in English.

## Choosing the language

The language is picked by
[`i18next-browser-languagedetector`](https://github.com/i18next/i18next-browser-languageDetector),
which checks, in order:

1. The `?lng=` query parameter, e.g. `?lng=nl` — handy for sharing a link in a specific language.
2. A previous choice, stored in `localStorage["i18nextLng"]` (see [Local storage](local-storage.md)).
3. The browser's preferred languages.

Visitors can switch at any time with the language links in the footer
(`src/components/LanguageLinks`). Each language is named in its own language (English,
Español, Deutsch, Nederlands), so visitors can find theirs whatever language is active.
The choice is stored and used on the next visit.

The `lang` attribute of the page's `<html>` element follows the active language
(`src/documentLanguage.tsx`), so screen readers and browsers treat the page as that
language. Each footer link carries its own `lang` attribute as well.

## Loading translations

Translations are not bundled with the app. [`i18next-http-backend`](https://github.com/i18next/i18next-http-backend)
fetches `/locales/<language>/translation.json` when a language is first used, so adding
a language doesn't grow the bundle. Until the translations arrive, the app shows a
`loading` placeholder (the `Suspense` boundary in `src/App.tsx`).

Because the files are served from `public/`, a deploy invalidates `/locales/*` in
CloudFront so visitors get updated translations right away (see
[`main.yml`](../.github/workflows/main.yml)).

## What is translated

Each `translation.json` has the same keys, grouped by part of the app:

| Group      | Used for                                                                 |
| ---------- | ------------------------------------------------------------------------ |
| `header`   | Title and subtitle.                                                      |
| `button`   | The buttons above the board.                                             |
| `edit`     | The edit modal ([Editing the board](board.md#editing-the-board)).        |
| `reset`    | The reset confirmation.                                                  |
| `import`   | The import error message.                                                |
| `faq`      | The "What is this?" section.                                             |
| `footer`   | Footer text.                                                             |
| `board`    | `board.language`: the language's own name, used in markdown exports.     |
| `flavours` | The names of the default flavours, by their `key`.                       |

Some values (in `faq` and `footer`) contain HTML links and are rendered as HTML, so
translations should keep the `<a href="...">` tags intact.

### Flavours

Default flavours in `public/flavours.json` carry a `key`; the board shows
`flavours.<key>` in the active language, so switching language relabels the board
immediately. Flavours added by the visitor have no `key` and always show their `name`
as typed (see [the data model](board.md#data-model)).

### Exports

- A [markdown export](markdown-format.md) writes default flavours in the active language
  and names the language in the title, e.g. `# Sunburst Smorgasbord - Nederlands`.
  Importing never translates: names are taken as written.
- An [image download](image-download.md) shows the labels in the active language.

## Adding a language

1. Copy `public/locales/en/translation.json` to `public/locales/<code>/translation.json`,
   using the [ISO 639-1](https://en.wikipedia.org/wiki/List_of_ISO_639-1_codes) code.
2. Translate every value, keeping the keys and any HTML tags. Set `board.language` to
   the language's own name (e.g. `Français`).
3. Add the language to `LANGUAGES` in `src/constants.tsx`, with its name in that
   language (e.g. `{ code: "fr", name: "Français" }`). This adds it to the footer.

Tests load all translation files from disk through `src/i18n.tests.tsx` (using
`i18next-fs-backend`), so no server is needed to test translated text.
